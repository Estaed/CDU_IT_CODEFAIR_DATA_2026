## Objective

Tarik's scenario (2026-09-21): can two communities talk to each other? A pairwise compare
screen was considered and dropped the same evening (PRD §4.2, sixth batch note below): a
mobile call needs a path at both ends, so the pair is decided by the weaker end, and the
information is already on the two community screens. What the scenario does give the
report is one sentence: the communities where `voice_sms` fails are not only unable to
call out, they are outside the mobile reach of every other community. The report team reads
`docs/FINDINGS.md`, which the pipeline writes; this task adds that sentence there with its
evidence table, in the file's existing convention.

## Execution Guide

Guidance, not a script, except where marked **fixed**.

  `voice_sms` verdict is `fails`, sorted by `bushtel_id`; `health_centre` is `Y` or `N` from
  the same column the pack's present list reads. Use the verdict the pipeline already
  computed; do not re-derive it.
- In `write_findings_md`, add one entry in the section where the service verdict counts
  live, following the file's line shape (`- <sentence> — evidence: <path> — value: <n> — run
  <date>`). **Fixed** sentence, numbers read at write time:
  `No public source records a mobile voice or SMS path in {n} of {total} communities
  ({people} people; {clinics} of them have a health centre). A mobile call needs a path at
  both ends, so these communities are outside the mobile reach of the other {total − n}
  as well as unable to call out; landlines, payphones and satellite phones are not in any
  source used here.`
- The caveat about landlines is part of the sentence on purpose: `fails` means "no public
  record of a path", not "proven unreachable".
