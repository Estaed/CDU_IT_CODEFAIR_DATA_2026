# Map layer byte budget — 2026-09-15

For PRD OQ13 (the new pack cap). Measurement only; no pipeline, app or pack file was
changed. Throwaway code: `reports/spike-map-bytes/fetch.py`, `reports/spike-map-bytes/measure.py`.

Current pack is 260,161 bytes against a 307,200 cap; `dist/index.html` is 318,741 bytes
(32,099 gzipped).

## Method

Every candidate layer was reduced to a set of Shapely polygons clipped to the Northern
Territory boundary (`data/raw/abs_ste_2021_shp.zip`, the full unsimplified NT multipolygon —
251 parts, 49,742 vertices — unioned once with `shapely.union_all`; clipping used a
prepared-geometry `contains`/`intersects` mask so only border-crossing polygons pay for a
real `intersection()` call, since a naive per-polygon `intersection()` against the full NT
union measured 374s on `accc_optus_4g` versus 6.4s masked). Each layer was then measured at
four points: unsimplified, and `shapely.simplify(tolerance, preserve_topology=True)` at
0.005, 0.01 and 0.02 degrees. At each point every vertex was projected with
`pipeline.outline.project` (the pack's 300x480 view-box projection, `K=30`), rounded to one
decimal by that function, and assembled into one `M x y L x y ... Z` path string per polygon
exterior ring (holes are dropped, matching `pipeline/outline.py`'s own convention for the NT
outline). A ring is dropped from the count and the path if its projected area is under 4
square units after simplification (equivalently, degree-space area under 4/900 ≈ 0.004444
deg², since `project()` is an isotropic affine map so area scales by exactly `K²`); this
filter is applied at every row, including "unsimplified," for a consistent kept-ring count
across the table. Bytes are `len(path.encode("utf-8"))`; the summary table's gzip figure
compresses the concatenation of every summed layer's path string at `compresslevel=9`.

ACCC coverage polygons were loaded through `pipeline.sources.accc.nt_polygons`, reusing the
pipeline's own bbox-filtered WKB cache in `data/out/cache/` (no re-parse of the KMLs). ABS
SA3/SA4 boundaries came from freshly downloaded shapefiles (see source registry). Highways
and exact town centroids were not measured — see below and the TBD list.

  `.gdb` zip (`https://d28rz98at9flks.cloudfront.net/147684/147684_01_May26_1.zip`, checked

  CC BY 4.0. Too large and licence too unclear for this spike; not downloaded.
- **NT Government Controlled Roads** (`https://data.nt.gov.au/dataset/nt-government-controlled-roads`,
  licence `cc-by` per the data.nt.gov.au package metadata, checked 2026-09-15): its one
  resource is a KMZ at
  `https://nt.gov.au/_media/images/driving_and_transport/roads_and_traffic_management/nt-government-controlled-road-maps.zip`.
  That host returned `403 Forbidden` to a scripted GET with a default `requests` user agent,
  a browser user agent, and a browser user agent plus a plausible `Referer` — consistent with
  bot protection in front of the file host rather than a login wall. Not downloaded within
  reasonable effort.

No highway polyline byte figure exists in this report.

## Towns

Not measured against a fetched source — noted only, per the task. Darwin, Katherine, Tennant
Creek, Alice Springs and Nhulunbuy as five points, using approximate town-centre coordinates
(not fetched from ABS or any dataset). Projected and serialised as
`[{"name":...,"x":...,"y":...}, ...]`: **208 bytes**, independent of tolerance — confirms the
task's expectation that town points are trivial next to the polygon layers above. A real
build would source these from ABS UCL (Urban Centre and Locality) 2021 centroids, or from a
roads dataset's place-name points if one is ever fetched.
