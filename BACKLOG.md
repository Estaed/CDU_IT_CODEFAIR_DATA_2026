## Why this file is separate from the task list

`tasks/Task-XX.md` is work that was *planned*. This is work that got *deferred* —
a shortcut taken under time pressure, a case knowingly not handled, a TODO that
would otherwise live in a code comment nobody reads again.

Kept out of the task files on purpose. A task file describes a slice that is
either DONE or not; mixing "and also this half-thing is still owed" into it
makes DONE mean nothing.

## Rules

- One line per item, newest at the bottom. Date it.
- Say **what** was skipped and **why** — the why is what lets a later reader
  decide whether it still matters. "Skipped input validation on the import
  form — demo was in two hours" is useful. "TODO: validation" is not.
- Link the task it came out of: `Task-07`.
- An item that turns out to matter gets promoted into a real task and removed
  from here. This file only holds things nobody has committed to yet.
- Review it when a group of tasks goes green, not continuously.

## Recording friction across sessions

Repeated friction here (a rule that keeps almost-holding, a tool trap hit twice)
follows the same schema as the brain's agent-experience ledger — append a line to
`reports/agent-experience.jsonl` with `kategori`, `belirti`, `kanit`,
`gecici_cozum`, `oneri`. The promotion call (turning a repeated friction into a
project rule) stays with the human; the tool only counts and surfaces repeats.
Tool: `D:\TarikOS\.claude\scripts\gardener.py` (`kaydet` / `rapor` / `aday`), run
against this project's own `reports/agent-experience.jsonl` — see
`D:\TarikOS\.claude\reports\README.md` for the full schema and the fingerprint's
word-based (non-semantic) limits.
